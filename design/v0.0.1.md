# v0.0.1: the first pre-release

**Status:** approved 2026-11-14; built on branch `dev-v0.0.1`. Changes made while building are marked *(build)*: the 2D keyboard as a desktop drawer (U10), fast typing serialised (D17), a Recorder view.

v0.0.1 is a **pre-release** with two aims:

1. **Every machine feature works.** That means Level II BASIC on an emulated Z80, the keyboard (games included), the cassette, the Video Display's controls, taking the machine apart, and a look inside it while it runs.
2. **The lessons work.** A set of lessons lets a middle-school class, or a first course in computer science, learn how a computer works on this machine.

The page is public from the first commit, so nothing on it exists only to collect feedback.

Related documents:
- the page's principles and decisions: [../docs/ui-design.md](../docs/ui-design.md)
- conventions for code, params and tests: [../docs/conventions.md](../docs/conventions.md)
- the machine's decisions (D1, D2, …): [decisions.md](decisions.md)
- sources: [../research/bibliography.md](../research/bibliography.md)

## 1. What a visitor can do in v0.0.1

- **Look at the whole system in 3D**, the default view. This means the keyboard unit with the computer inside, the Video Display, the CTR-80 cassette recorder, the power supply and the cables, on a desk.
  - Views: Desk, Keyboard, Screen, Rear, Inside.
  - **See inside** turns the case to glass. The view is from below, where the main board's chips hang, and the chips light up as the machine runs.
- **Switch to 2D and back** with a `[2D | 3D]` toggle on the stage.
  - 2D shows flat views of the machine's own faces: the Video Display from the front, the recorder from above and the keyboard unit from above. They are drawn from the same parameters as the 3D model.
  - The picture is a sharp canvas.
  - On a phone, 2D is how you type.
- **Switch it on and use Level II BASIC.**
  - Type on your own keyboard, held keys included, so games play. Or click or tap the Model I's keys, in 3D or 2D.
  - RESET, and 32-column mode.
  - The Video Display's power, contrast and brightness.
- **Use the cassette.**
  - Insert a blank tape or one of our own sample tapes, or open your own `.cas` or `.wav`.
  - `CSAVE`, `CLOAD`, and `SYSTEM` for machine code.
  - The recorder's six keys, the computer's motor relay, the tape's sound, and fast tape.
  - Download any tape as `.cas` or `.wav`.
- **Take it apart, with the power off**, in the real order. The machine refuses to switch on while it is apart, and *Put it all back* is one press.
- **Watch the machine's idea at work**, in five tools in the dock:
  - **Lessons:** the course (§3).
  - **Video RAM:** 64 × 16 bytes, live. A cell inspector shows a byte, its dots from the character generator, or its 2 × 3 blocks.
  - **Keyboard:** the 8 × 8 matrix. Shows the addresses the program reads and the bytes it gets back.
  - **Cassette:** what a tape holds, its position, and the tape under the head as pulses, bits, bytes and what each byte is.
  - **CPU & Memory:** the Z80's registers and flags, and the next instruction disassembled. A live memory map (ROM, keyboard, video, RAM) and a memory dump that follows PC. Pause, Step, Run to, and a slow clock.
- **Read About:** the version, the sources, the licences (the Level II ROM's notice among them), and what the simulator simplifies.

**Platforms:** desktop browsers (Chrome, Edge, Safari, Firefox), and phones with the same app in the same order (8800 P9). English only, with every text a message key.

## 2. What is carried over, and how

The machine, its cassette, its 3D model and its first lesson were built and checked in a private prototype before this repository existed. **Nothing is copied from it as it stands.** Each piece is ported with review:

1. **Read** it whole.
2. **Review** every rule in it against the source it cites (`research/`, the manuals, the ROM's own behaviour).
3. **Improve** names, types, comments and structure to this repository's conventions. Any departure from what was there is recorded in a decision (D1, D2, …).
4. **Verify**, with tests written from the sources, not from the old code's output. A test's expected value cites its source.

Every comment and document is reworded to stand on its own: no milestone names and no to-do lists.

The prototype's pages are **not** carried over. Their layout and workflow logic are redesigned here (`docs/ui-design.md`). There are no developer pages: the one page is `index.html`, and `?selftest` runs the acceptance checks in it.

| Part | What is settled, to port with review |
|---|---|
| The machine | Memory map; port FF; NMI on RESET; the 7-bit video RAM with bit 6 rebuilt; the keyboard matrix with row reads; typed keys gated on the program's reads; held host keys as the Model I's; the clock at 1.774 MHz with exact T-states |
| Dependencies | three.js 0.186.1; DrGoldfire's `Z80.js` (MIT) at a pinned commit, unchanged but for one `export` line; xtrs's character set "CG 1"; all pinned with SHA-256. ZEXDOC must pass all 67 groups (opt-in test, not committed: GPL) |
| The ROM | Level II BASIC v1.2, 12 KB, under `roms/NOTICE` |
| The cassette | Pulses at Level II's measured timing; `.cas` and `.wav` both ways; `SYSTEM` tapes; the CTR-80's keys and the REM relay |
| The 3D model | `params/` and the Blender scripts, rebuilt here (`pnpm build:model`); named parts for the chips, the door, the cassette and its reels; the logos and the Michroma font |
| Lesson 1 | "The screen is memory": its steps as data (type, show, check), and its teacher notes |

Visitors bring their own tapes. No third-party software ships, and nothing links to archives.

## 3. The lessons

The course is one track for both audiences.
- Each lesson is written for a middle-school reader.
- A *Going further* aside in each carries the computer-science depth (binary, addressing, memory-mapped I/O, encoding, the fetch–execute cycle).
- Each lesson has teacher notes in `lessons/`: aims, timing, talking points, the questions students ask, and the answers.

Every lesson follows the same structure:
- **Steps are data.** A step has a title, its text, *Type it* (keys typed on the Model I's own keyboard), *Show me* (a view, a Show, or a tool and its selection, which never works the machine), and a check on the machine that ticks it done.
- **Every lesson runs end to end in `node --test`** on a headless machine.

| # | Lesson | The idea | The machine shows it by |
|---|---|---|---|
| 1 | **Meet the TRS-80** | A computer sold ready to use, in 1977. Its parts, and what each does | A tour in 3D (keyboard unit, display, recorder, power supply), switching on, `MEMORY SIZE?`, `READY` |
| 2 | **Talk to BASIC** | A program is a list of instructions the computer follows in order | `PRINT`, then a numbered program, `RUN`, `LIST`, a loop, `INPUT` |
| 3 | **The screen is memory** | 1,024 bytes are the picture | `POKE` a character; draw a box with `SET`; find its corner in the Video RAM; predict a byte before looking |
| 4 | **The keyboard is memory** | Keys are switches in a matrix, read as bytes | `PEEK(14400)` with arrows held; the Keyboard tool's row reads; a short program that moves a block while a key is held |
| 5 | **Programs as sound** | A program saved as pulses on an ordinary tape | `CSAVE` onto a blank tape; the Cassette tool's pulses, bits and bytes; `CLOAD` it back |
| 6 | **Inside the CPU** | The CPU fetches, decodes and executes one instruction after another, and memory holds both code and data | Machine code put in with `POKE`, run with `USR`. Pause and Step in CPU & Memory, watching PC, HL and the screen fill. See inside: the RAM chips light up as the code runs |

Lesson 1's research task (*draw with `SET`, then find the picture as bytes*) is lesson 3 here. Lesson 6 needs the CPU & Memory tool, which is in v0.0.1.

## 4. The page, in outline

The full rules are in `docs/ui-design.md`. They follow the 8800 simulator's principles (P1–P11), adapted.

```
┌ [logo] TRS-80 Simulator   [▤ Tapes ▾] [▶ Programs ▾]                                [ⓘ] ┐  top bar
├─────────────────────────────────────────────────────────────────────────────────────────┤
│ [⏻ Computer] [⏻ Display] [RESET]          [⌂] [− +] [Desk ▾] [Show ▾]  [2D | 3D]        │  stage band
│                                                                                         │
│                    THE STAGE: the desk in 3D, or the flat views in 2D                   │
│                                                                    [Put it all back]    │
├══════════════════════════════════════ drag ═════════════════════════════════════════════┤
│ Lessons   Video RAM   Keyboard   Cassette   CPU & Memory                              ▾ │  dock
│ …                                                                                       │
├─────────────────────────────────────────────────────────────────────────────────────────┤
│ READY. Type on your keyboard: Esc is BREAK, Enter is ENTER.                             │  status line
└─────────────────────────────────────────────────────────────────────────────────────────┘
```

- **3D is the default** on a first visit. The choice is then remembered, and a link can carry it as `#view=3d` or `#view=2d`.
- Going to 2D flies the camera to the screen and cross-fades to the flat views. Going back reverses it. A double-click on the CRT in 3D also goes to 2D.
- The 3D scene stops rendering while 2D is shown.
- **POWER and RESET:** on the machine they are on the keyboard unit's rear. They stay clickable there in 3D, and the stage band's helper buttons reach them too.
  - In 2D the flat views carry them, so the helpers are not shown there: P2, one home.
- **Taking apart** needs the computer off. Nothing switches on while the machine is apart. Going to 2D puts it back together and says so.

## 5. Stages

These are internal stages of the work, not public milestones. Each one ends with `pnpm check` (refs, types, tests) and `reuse lint` passing, and a commit.

| Stage | Delivers |
|---|---|
| **S0. The repository** | Licences, `REUSE.toml`, `package.json` (pnpm, Node 24), strict JSDoc `tsconfig.json`, editor and git config. Tools: vendor, stamp, check-refs, serve. CI: tests, REUSE, check-refs; Pages deploys `main` once they pass |
| **S1. The machine** | Ported with review: the Z80 wrapper, machine, clock, keys, host keys, character set, ROM loading. Tests: ZEXDOC (opt-in), boot to `READY`, keys, video RAM, NMI |
| **S2. The cassette** | Ported with review: tape and pulses, recorder, `.cas`, `.wav`, `SYSTEM` tapes, our sample tapes |
| **S3. The model** | `params/`, the Blender scripts and the `.glb`, rebuilt here; the node contract test (every named part the page uses) and budgets |
| **S4. The CPU & Memory core** | A Z80 disassembler tested against Zilog's tables; pause, step, run-to and slow clock in the clock; the memory map. No DOM |
| **S5. The page** | Top bar, stage (3D viewer, flat 2D views, the toggle and the flight), the dock and its five tools, status line, About, message keys, `?selftest`. Phone layouts |
| **S6. The lessons** | Six lessons as data, teacher notes, an end-to-end test per lesson |
| **S7. The release** | README (8800's shape), CHANGELOG, screenshots, a manual pass in Chrome, Safari and Firefox and on a phone, `pnpm version 0.0.1`, the release PR, then the `v0.0.1` tag marked as a pre-release |

## 7. Not in v0.0.1

- Level I BASIC and the 1977 machine (no keypad);
- lower case (the eighth video RAM chip);
- the Expansion Interface and disks;
- a Model III;
- other languages;
- an assembler (the lesson uses `POKE` and `USR`, as owners did).
